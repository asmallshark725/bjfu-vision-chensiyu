## 一帧图像经历了什么

1. `main.cpp` 中的 `video.read(frame)`：解码并读取下一张图片，存进 `cv::Mat`。
2. `findLights()` 中的 `inRange()`：把三个通道都达到亮度门槛的像素设为 255，其他为 0，形成二值掩膜。
3. `morphologyEx(... MORPH_CLOSE ...)`：先膨胀再腐蚀，用 3×3 邻域连接小断裂、填小空隙。这个大小会影响结果，过大会粘连相邻目标。
4. `findContours()`：找出白色区域的边界。`minAreaRect()` 用可旋转矩形概括它，得到中心、宽高和方向。
5. `identifyColor()`：通过灯条附近原图像素的红蓝通道差，判断阵营。白色亮芯定位形状，附近有色部分提供颜色证据。
6. `matchLights()`：比较颜色、方向、长度和相对位置，将两根灯条构造成已有的 `Armor`。
7. `PnPSolver::solve()`：用四角像素坐标、已知物理尺寸、相机内参和畸变参数求位姿。
8. `drawArmor()`：把四角、中心和有效距离画在这一帧上，随后显示或保存。

## 颜色空间、二值化与形态学

颜色空间是表达颜色的坐标方式。本项目继续用 OpenCV 默认的 BGR，每个像素的三个通道对应蓝、绿、红；HSV 则使用色调、饱和度和明亮程度。

二值化是按规则把像素分为保留/排除两类。掩膜上的白色只代表通过了当前条件，不代表已经识别成装甲板。

形态学通过邻域改变二值区域：膨胀扩大白色区域，腐蚀缩小白色区域。开运算先腐蚀后膨胀，常用于清除小白点；闭运算先膨胀后腐蚀，常用于填补小空隙。

本项目先用亮芯找几何候选，再仅在候选灯条附近判断颜色；滑条调整的亮度门槛同时作用于亮芯提取与局部颜色统计。

## 相机标定和 PnP 的区别

相机标定先通过标定图案和多个视角求出内参矩阵、镜头畸变参数。它描述相机怎样把空间位置变成像素坐标。使用期间需要保持匹配的相机、镜头、分辨率等条件。

PnP 在运行时使用这些已知相机参数，把物体上的已知 3D 点与图片中的对应 2D 点配起来，求物体相对相机的位置和朝向。本次读取课程已有标定，没有声称重新做过一次实机相机标定。

`config/camera.yml` 中实际尺寸使用米，所以 `tvec` 也是米。距离使用三个平移分量的长度，不只读取前向深度 `tz`。

`std::optional<PoseResult>` 表示“可能有一个有效解，也可能没有”。角点退化、位姿不合理或误差过大时，本帧没有距离结果；程序不会沿用上一帧距离来掩盖失败。

## 建议阅读顺序

先在 `main.cpp` 找到 `read → detect → solve → draw`，说明四个调用分别输入/输出什么。随后读 `findLights` 和 `identifyColor`，最后再读配对中的投影和 PnP 的点序。

用来练英语的基本词：mask（掩膜）、contour（轮廓）、bounding rectangle（外接矩形）、calibration（标定）、reprojection error（重投影误差）。参考资料及原文链接在上一级 README 的“来源”部分。
