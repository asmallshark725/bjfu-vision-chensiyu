# Task3（视觉方向）：Hello OOP

本项目对应学校《算法组零基础培训任务书》第 3.1 节。通过 `Light`、`Armor` 和 `Detector` 等类组织一个基于手动灯条数据的检测演示，为后续装甲板图像识别搭建程序结构。

## 1. 功能与任务要求对应

| 任务要求 | 本项目实现 |
| --- | --- |
| `Light` 包含中心点、长度、宽度、倾斜角，并计算长宽比 | 使用私有数据成员保存灯条属性，提供读取接口和 `aspectRatio()` |
| `Armor` 由两个 `Light` 构造，提供中心点与平行判断 | 通过成员初始化列表构造两根灯条成员，计算中心坐标并判断角度差 |
| 抽象 `Detector` 派生红蓝检测器，使用智能指针切换 | `detect()` 为纯虚函数；`main` 读取 `color`，创建相应派生对象并交给 `std::unique_ptr<Detector>` 管理 |
| 六根假灯条两两配对，输出满足条件的装甲板 | `matchArmors()` 枚举不同下标的灯条对，输出符合角度差条件的候选及中心坐标 |

当前红蓝模式共用同一组六根手动灯条数据和几何配对逻辑，演示运行时多态和模块组织。这里的颜色输入用于选择检测器类型，程序尚未从图像中提取灯条或识别红蓝像素。

## 3. 编译与运行

开发环境：WSL Ubuntu 22.04、g++ 11.4.0、C++17、CMake 3.22.1。

以下命令从包含本项目源码的仓库根目录执行：

```bash
cd task3
cmake -S . -B build
cmake --build build
./build/armor_demo
```

程序启动后，根据提示输入 `red` 或 `blue`，分别选择红色或蓝色检测器。输入其他字符串时，程序提示“颜色无效”，并以返回值 `1` 退出。

修改源码后，重新执行构建命令；构建成功后再运行程序。

## 4. 类的成员、职责与关系

### Light：保存单根灯条

私有数据成员：

| 成员 | 含义 |
| --- | --- |
| `centerX`、`centerY` | 灯条中心坐标 |
| `length` | 灯条长度 |
| `width` | 灯条宽度 |
| `angle` | 灯条倾斜角，单位为度 |

主要成员函数：

- 构造函数接收中心坐标、长度、宽度和倾斜角。
- `getCenterX()`、`getCenterY()`、`getangle()` 读取对应属性。
- `aspectRatio()` 返回 `length / width`。
- `setWidth()` 检查宽度；当输入小于或等于零时提示错误，并保留原宽度。构造期间使用同一接口检查传入宽度，若被拒绝则保留成员的默认宽度 `4.0`。
- 析构函数当前为空。

读取属性和计算长宽比的成员函数带有 `const`，表达这些操作不修改对象的数据成员。

### Armor：组合两根灯条

私有成员为 `Light left` 和 `Light right`。构造函数接收两个 `const Light&`，使用 `left(first)`、`right(second)` 分别初始化成员，保存传入灯条的副本。

主要成员函数：

- `getCenterX()`：返回两根灯条中心横坐标的平均值。
- `getCenterY()`：返回两根灯条中心纵坐标的平均值。
- `isParallel(maxAngleDiff)`：计算两灯条倾斜角之差的绝对值，判断是否不大于给定阈值。

`Armor` 与 `Light` 是组合关系：一个 `Armor` 对象包含两个独立的 `Light` 成员对象。

### Detector：规定检测器接口

当前没有显式定义的数据成员，主要成员函数为：

- `start() const`：输出检测器启动提示。
- `virtual void detect() const = 0`：规定具体检测器需要提供的检测接口。
- 虚析构函数 `virtual ~Detector()`：使通过基类指针销毁派生对象时，能够正确执行派生类和基类的析构过程。

### RedDetector 与 BlueDetector：具体检测器

两个类都公开继承 `Detector`，当前没有新增数据成员。各自重写 `detect() const`，输出对应颜色的检测提示，然后调用共同的 `matchArmors()` 完成假数据配对；各自的析构函数输出销毁提示。

### 普通函数与主程序

- `matchArmors()` 是普通函数，负责构造六根灯条、枚举配对、筛选和输出结果。
- `runDetector(const Detector&)` 是普通函数，依次调用检测器的 `start()` 和虚函数 `detect()`。
- `main` 根据输入创建 `RedDetector` 或 `BlueDetector`，由 `std::unique_ptr<Detector>` 独占管理，调用 `runDetector(*detector)` 执行统一流程。
- 智能指针离开作用域时自动销毁所管理的对象；先执行具体派生类的析构函数，再执行基类析构函数，并释放动态分配的对象存储空间。

## 5. 为什么 Detector 设计成抽象基类

`Detector` 用于统一约定检测接口，通用基类本身不代表某一种具体检测方式，因此将 `detect()` 声明为纯虚函数，使它不能直接实例化。具体的红色、蓝色检测器分别实现该接口，主程序通过基类指针或引用调用时会执行实际对象对应的版本。这样添加新的检测器类型时，可以复用已有的统一调用流程。

## 6. 假数据与筛选条件

六根灯条的长度均为 `20.0`，宽度均为 `4.0`，长宽比均为 `5.0`。中心坐标使用假想图像坐标；角度单位为度，约定竖直方向为 `0`，顺时针为正、逆时针为负。

| 下标 | 中心 X | 中心 Y | 长度 | 宽度 | 倾斜角 |
| --- | --- | --- | --- | --- | --- |
| 0 | 100 | 80 | 20 | 4 | 5 |
| 1 | 160 | 84 | 20 | 4 | 7 |
| 2 | 300 | 100 | 20 | 4 | 18 |
| 3 | 360 | 102 | 20 | 4 | 20 |
| 4 | 500 | 120 | 20 | 4 | -15 |
| 5 | 560 | 118 | 20 | 4 | -12 |

内层循环从 `j = i + 1` 开始，使每根灯条不与自己配对，且同一组灯条只枚举一次。六根灯条共形成 `6 × 5 / 2 = 15` 组不同配对。

本次设置 `maxAngleDiff = 5.0`，判定条件为两灯条角度差的绝对值不大于 `5.0` 度。该阈值是本项目为演示选择的参数，任务书未指定固定阈值。

当前使用这组小倾角数据演示角度接近的判断；满足条件的结果称为候选装甲板，筛选没有加入灯条长度差、相对位置等进一步几何约束。
